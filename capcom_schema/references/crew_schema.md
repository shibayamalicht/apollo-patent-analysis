# CREW スキーマ

## 対象ファイル
`data/crew_network.json`（要約版）

## モジュール概要
CREW は発明者/出願人の共起ネットワーク分析モジュール。特許の共同発明者・共同出願人の関係をグラフ構造として抽出し、媒介中心性（betweenness centrality）によるキーパーソン特定、Louvain法によるコミュニティ検出、技術ブローカー分析を行う。

## JSONスキーマ（`crew_network.json` — 上位ノードの指標サマリ）

CREW は共起ネットワークの **上位ノードの指標サマリ** を保存する（グラフ全体の nodes/edges 配列は保存しない。全ノードは画面の Metrics タブ／CSV で確認可能）。

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `mode` | string | `"発明者ネットワーク"` または `"企業アライアンス"` |
| `color_mode` | string | 最後に選択した色分け基準（コミュニティ (派閥)／技術トピック／媒介中心性／技術ブローカー／生産性スコア／急上昇スコア） |
| `metric_guide` | string | `color_mode` の指標の読み方ガイド文 |
| `node_count` | int | ネットワークの全ノード数 |
| `shown_top` | int | `top_nodes` の件数（上限15） |
| `sorted_by` | string | `top_nodes` のソート基準（数値指標名。カテゴリ選択時は「媒介中心性」で代表化） |
| `top_nodes` | array | `sorted_by` 降順の上位15ノード。各レコードに全指標カラムを含む（下記） |
| `top_by_metric` | object | **指標別の上位15ノード**（v9 追加）。キー=指標名（媒介中心性／技術ブローカー／生産性スコア／急上昇スコア）、値=その指標降順トップ15のレコード配列。**最後に選んだ `color_mode` に関係なく、各指標のトップ層が常に揃う** |

### `top_nodes` / `top_by_metric[*]` のレコード構造（共通）

| キー | 型 | 説明 |
|------|-----|------|
| `ノード` | string | 発明者名／出願人名 |
| `出願数` | int | 当該ノードの関与特許数 |
| `コミュニティ` | int | 所属コミュニティID（Louvain 法） |
| `媒介中心性` | float | betweenness centrality。異なる派閥を橋渡しする結節点度 |
| `技術ブローカー` | float | 異なるコミュニティ間を橋渡しする度合い |
| `生産性スコア` | float | 出願数/(次数+1)。少人数連携での多産度（R&D効率） |
| `急上昇スコア` | float | 直近の活動拡大度（新興プレイヤーの早期警戒） |

> 💡 **複数指標のトップ層を語るときは `top_by_metric` を使う**（`top_nodes` は最後の `sorted_by` 依存で取りこぼしが起きる）。
> 💡 ネットワーク図は **色分け基準ごとに別スナップショット** として保存され、画像ファイル名（`crew_network_<基準>.png`）・タイトル（「色分け: 〇〇」）に基準名が入る。**指標ごとの図を個別に提示・分析できる**（分析しない図は貼らない）。
> ⚠️ ネットワーク密度・エッジ・コミュニティ全容はこのサマリ JSON には含まれない（スナップショットの説明文／画面で参照）。

### サンプル構造

```json
{
  "mode": "発明者ネットワーク",
  "color_mode": "媒介中心性",
  "metric_guide": "高=異なる派閥を橋渡しする結節点…",
  "node_count": 420,
  "shown_top": 15,
  "sorted_by": "媒介中心性",
  "top_nodes": [
    {"ノード": "山田太郎", "出願数": 32, "コミュニティ": 2, "媒介中心性": 0.184,
     "技術ブローカー": 0.62, "生産性スコア": 1.8, "急上昇スコア": 0.4}
  ],
  "top_by_metric": {
    "媒介中心性":   [ /* 媒介中心性 降順トップ15 */ ],
    "技術ブローカー": [ /* 技術ブローカー 降順トップ15 */ ],
    "生産性スコア":   [ /* 生産性スコア 降順トップ15 */ ],
    "急上昇スコア":   [ /* 急上昇スコア 降順トップ15 */ ]
  }
}
```

> 📌 下記「解釈ガイドライン」は各指標の**意味**の説明。JSON のフィールド名は日本語（媒介中心性／技術ブローカー／生産性スコア／急上昇スコア／出願数／コミュニティ）である点に注意（旧版の英語名 betweenness/patent_count 等ではない）。density・communities 詳細はサマリ JSON 非収録。

## 解釈ガイドライン

### 媒介中心性（betweenness）
- 0.0〜1.0の範囲。値が高いほどネットワーク内で情報・技術の橋渡し役として重要な位置にいることを示す。
- betweennessが高いノードは、異なる技術グループや組織間の接点となるキーパーソン/キー組織である可能性が高い。
- 特許数（patent_count）が少なくてもbetweennessが高い場合、少数精鋭で戦略的な位置にいることを意味する。

### コミュニティ
- Louvain法により検出された密結合グループ。同一コミュニティ内のノードは互いに強く結びついている。
- コミュニティは技術テーマ、組織系列、研究グループなどに対応することが多い。
- `communities.top_members` は各コミュニティの中核人物/組織を示す。

### 技術ブローカー（brokerage）
- 異なるコミュニティ間を橋渡しするノードの度合いを定量化したスコア。
- ブローカースコアが高いノードは、複数の技術領域やコミュニティを横断して活動している。
- betweennessとbrokerageの両方が高いノードは、ネットワーク全体のハブとして特に注目すべき存在。

### 急上昇スコア（rising_score）
- 近年の活動量増加率を示す指標。正の値が大きいほど、最近急速に活動を拡大していることを意味する。
- 新興プレイヤーの発見に有用。patent_countは少なくてもrising_scoreが高い場合、今後の注目対象となりうる。

### ネットワーク密度（density）
- 0.0に近い場合: 疎なネットワーク。特定のグループ間でのみ共起が発生しており、全体的な協業は少ない。
- 1.0に近い場合: 密なネットワーク。多くのノードが互いに共起しており、広範な協業関係がある。
- 一般的に特許ネットワークは疎（density < 0.1）になりやすい。

## レポートでの典型的な言及パターン

### ネットワーク構造の概観
- 「共起ネットワークは**N名**のノードと**M本**のエッジで構成され、密度は**D**である」
- 「Louvain法により**K個**のコミュニティが検出された。最大コミュニティは**X名**で構成される」
- 「ネットワーク密度が**D**と低いことから、特定のグループ内での共同研究が中心であり、グループ横断的な協業は限定的である」

### キーパーソン/キー組織の特定
- 「媒介中心性が最も高いのは{id}（betweenness: **B**, patent_count: **P**件）であり、ネットワーク全体の情報ハブとして機能している」
- 「{id}はbetweennessとbrokerageの両方が高く、コミュニティ{A}と{B}を橋渡しする技術ブローカーとしての役割を果たしている」
- 「{id}はpatent_countが**P**件と少ないものの、rising_scoreが**R**と高く、近年急速に活動を拡大している新興プレイヤーである」

### コミュニティ間の関係
- 「コミュニティ{A}（{top_members}を中心とする**S名**のグループ）とコミュニティ{B}は、{broker_id}を介して接続されている」
- 「コミュニティ{A}は{topics}に関する技術テーマを共有するグループであり、組織的にも{共通点}が見られる」
- 「孤立したコミュニティ{C}は独自の技術領域で活動しており、他グループとの協業拡大の余地がある」

### 時系列的な変化の示唆
- 「rising_score上位のノードは{id_1}, {id_2}, {id_3}であり、いずれもコミュニティ{X}に属している。この領域での活動活発化が示唆される」
- 「従来の中心的プレイヤーである{id}のrising_scoreは低く、近年の活動は停滞傾向にある」
