## 0. 位置づけ（最重要・ここを外すと本末転倒）

本ガイドの三技法は、**「正しく見えるが間違っている」報告書**——体裁は完璧で25個の機械検査を全て通るのに、分析として破綻している報告書——への対策である。リチャーズ・ホイヤー『インテリジェンス分析の心理学』の構造化分析技法を、機械のアナリスト（執筆AI）への強制＋人間による監査、という形で移植する。

**貫く一行: 機械の仕事は「正しさの判定」ではなく「注意の誘導」である。**

- 三技法の枠（`#competing-hypotheses` / `#linchpin` / `#ach-matrix`）は、結論の正しさを**保証しない**。判断（対立仮説・弁別材料・要の前提・崩れる条件）を、人間が安く監査できる形に**外部化**する。
- **内的整合は現実との対応ではない**。枠を埋めて筋が通っても、現実と合っている保証にはならない。立派な表ほど「正しく見える」危険はむしろ上がる。だからこそ、監査すべき箇所（×のセル・弁別材料・崩れる条件）を人間の目の前に並べる。
- 三技法の適用範囲は**意図的に非対称**である: ACH が最も広く（結論・提言章で必須、各 deep_dive の統合インサイト節は推奨）、リンチピンは冒頭の主要結論のみ、ミラーイメージング点検は立場が自社（self）以外のときのみ。
- **用語（v9.1）**: 本ガイドの技法名（ACH・対立仮説・弁別材料・残った仮説・非弁別・リンチピン・ミラーイメージング）は**内部用語**である。レポート本文・別冊では `terminology.md` §2-F の**読者向け呼称**——「別解釈」「決め手」「最も矛盾の少ない解釈」「結論の前提と見直しのサイン」「相手の立場から見た合理性」——を使う（Check 8f が技法名の本文露出を警告。ヘルパーのラベルは読者向け呼称で自動描画される）。

## 1. 技法1: ACH（競合仮説分析）— 横の広がり

### 1-1. 仕組み（理解せずに形だけ真似ると逆効果）

**仕組み1: 反証を先に置く。** 通常の失敗は確証バイアス——まず結論の筋書きを見つけ、次にそれを支持する材料を積み上げる。ACH はこれを反転させる。複数の対立仮説を先に並べ、各仮説を**反証しにいく**。最も確からしい結論とは「支持する材料が最も多い仮説」ではなく、「**それに反する材料が最も少ない仮説**」である。

**仕組み2: 弁別力（最重要・最も誤解される）。** ほとんどの材料は**複数の仮説と両立する**ので、実は判断の役に立たない。「クラスタXの出願が増えている」は「領域全体が成長している」とも「一社が大量に出願しているだけ」とも両立する——だから成長という結論の裏付けに**ならない**。判断を動かすのは、**ある対立仮説と食い違う材料**だけである。ゆえに `counter_evidence`（弁別材料）とは「主結論を支持する材料」ではなく「**退けたい対立仮説と矛盾する具体的な材料**」でなければならない。

**「かかし」の禁止（新たな水増しのリスク）。** 退けた対立仮説が、そもそもどの材料にも支持されていない弱い仮説なら、それを退けるのはタダで、意味がない。真の ACH は、**実際に支持のあった、もっともらしい対立仮説**を、弁別材料によって（そのもっともらしさにもかかわらず）退ける。「対立仮説を立てて退ける」という儀式だけ踏んで中身が空の枠を並べるのは水増しであり、Check 19 と同種の不正である。

**本ガイドの ACH は教科書からの意図的な簡約版。** 本来の ACH は仮説×材料の総当たり表を組むが、全結論に毎回課すのは重すぎる。よって「**最も強い対立仮説（複数可）＋その弁別材料**」という軽量版を採る。総当たりの網羅性は捨てるが、「見落としていたはずの代替を名指しし、食い違う材料で退ける」という規律の核は保つ。中心的な問い1つだけは総当たりに近い形（§2 の ACH マトリクス）で扱う。

### 1-2. 本ドメインの典型的な対立仮説（このタネから書き始める）

| 主結論の型 | 立てるべき対立仮説 | 弁別材料の例 |
|---|---|---|
| **「技術領域Xは成長期にある」**（見かけの成長） | A: 一社の出願急増が領域全体の成長に見えているだけ／B: DB収録範囲の変化・再分類による見かけの増加 | クラスタ内出願人HHIの経年変化（真の成長なら新規参入で**下がる**、一社の急増なら高止まり）、新規出願人名の有無、収録年情報の変更有無、増加がクラスタ横断か一極か |
| **「企業Xが技術リーダーである」**（リーダーの断定） | A: Xは大量出願者（防衛的な出願網・価値の低い出願）で件数が多いだけ／B: Xのリードは過去のもので直近の勢いは別の企業にある | 権利化率（基本統計）、Xの直近出願の時系列（最前線から遅れていないか）、直近N年に限った出願シェア |
| **「空白セルZは未開拓の機会である」**（ホワイトスペース＝「吠えなかった犬」） | A: 誰も追わない"死んだ"組み合わせ（技術的に成り立たない・需要がない）——**無いこと自体が逆向きの情報**／B: 分類軸の定義上そもそも希少なだけの見かけの空白 | そのセルに学術論文などの活動があるか（環境分析）、過去に試みて放棄された痕跡、隣接セルの動態 |

**空白セルを一律に機会と読むのは本ドメインで最も多い誤りの一つ**である。ルール分類のホワイトスペース分析・俯瞰図分析のホワイトスペース節では、必ず対立仮説A（死んだ組み合わせ）を検討してから機会と結論すること。

### 1-3. 書き方と適用範囲

- ヘルパー: `#competing-hypotheses(main: "...", rivals: ((hypothesis: "...", counter_evidence: "..."), ...))`（定義と使用例は `report_style.typ`）
- **必須**: 結論・提言章（戦略的提言）の主要結論。主要結論が3個以上なら `#competing-hypotheses` を2個以上、1〜2個なら1個以上（`phase_d_gate.sh` Check 30 が数える。1個も無ければ不合格）
- **推奨**（必須ではない）: 各 deep_dive の「統合的戦略インサイト」節。「本母集団は成長期にある」のような一つの筋書きだけで節を閉じそうになったら、ここの対立仮説を1つ検討する
- 対立仮説は各結論で最低1個。報告書冒頭の主結論は2個以上を推奨
- `counter_evidence` には**出所をたどれる要素**（数値＋単位・特許番号・`#footnote`）を必ず含める（Check 30b が欠落を警告。「これは考えにくい」だけの手を振る棄却を許さない）
- **中心的な問い（報告書の見出し級の結論）には inline の枠を置かず、§2 のマトリクスに寄せる**（重複を作らない）

### 1-4. 正直な限界

Check 30 は「ACH をやったか」を検査できるが「ACH が良いか」は検査できない。かかし（弱い対立仮説）という新しい水増しは機械では判定できない。Check 30b は弁別材料に具体的な材料があるかまでは見るが、その材料が**本当に対立仮説を退けているか**（弁別力の正しさ）は判定できない。質の最終的な担保は人間の監査である。枠の役割は、監査すべき箇所を人間の目の前に並べることに尽きる。

## 2. ACH マトリクス（仮説検証サマリ）— 中心的な問いを一望する

### 2-1. 描く対象と置き場所

- **報告書の中心的な問い1つに限って描く**（各モジュール・各結論ごとには描かない＝重さを抑える）
- 置き場所: 結論・提言章の冒頭、または「仮説検証サマリー」章
- inline の `#competing-hypotheses` との役割分担: 中心的な問いはマトリクスで扱い、inline の枠を重ねない。inline は中心的でない結論に使う

### 2-2. 表の読み方・書き方

- 列＝仮説、行＝材料（**出所をたどれる観測**: 数値・特許番号・脚注つき）、セル＝○（両立）／×（食い違い）／—（判断保留）
- **×こそが判断を動かす**: すべての仮説と両立する行（全列○）は弁別力ゼロであり、何も判断していない。ヘルパーが自動で灰色化し「（非弁別）」を付す
- **残った仮説**＝×が最も少ない仮説（最も反証されにくい仮説）。ヘルパーが ◎ を自動で付す
- 🚫 **非弁別の行だけで表を埋めない**（全行が○の表は外部化の体裁だけの水増し。Check 33 が×皆無を警告）
- 🚫 **×の判断を結論に合わせて後付けしない**。先に材料を見てからセルを埋める（この後付けは機械では検出できない——だからこそ、×のセルの根拠を脚注や本文で示し、人間が個々の×を名指しで反証できるようにする）

### 2-3. 三つの環（マトリクス → 結論 → 提言）— 分析の芝居を作らない

**防ぎたいのは「分析の芝居」**——中心的な問いには立派なマトリクスを描いておきながら、結論や提言はモデルの既定の筋書きで別に書かれ、ACH の結果と切れている状態。これでは技法を課しても答えは変わらず、儀式だけが増える。

- **環1（マトリクス → 結論）**: 表の直後に、**最も矛盾の少ない解釈（＝採用した結論）を明示する**段落（または `#conclusion-box`）を必ず書く。単に「Zである」ではなく「別解釈X・Yはそれぞれ事実◯◯（×）と矛盾するため退け、最も矛盾の少ない解釈Zを採用する」と、**どの決め手がどの別解釈を退けたか**まで書く
- **環2（結論 → 提言）**: 戦略的提言の各提言は、**採用した結論を前提として名指しで置く**。例:「本領域は見かけの成長であり実体は一社の急増（仮説検証サマリーで採用した結論）である。したがって、面での参入ではなく当該一社への個別対応を推奨する」
- **環3（提言のリンチピンとの統合）**: 提言のリンチピン（§3）の要の前提に「残った仮説」を据え、`overturns_if` に「退けたはずの対立仮説（例: 真の領域成長）が後から裏づけられたら」を書く。こうして **ACH の結論が提言の脚になり、結論が覆れば提言も覆る**という依存が明示される
- `phase_d_gate.sh` Check 34 が「提言が ACH の結論（残った仮説）を参照しているか」を検査する（切れて宙に浮いた提言＝ACH が飾りだった証拠、を表に出す）

### 2-4. 正直な限界

マトリクスは見た目に説得力があり、それゆえ諸刃である。**描画は内的整合と監査可能性を上げるが、現実との対応は上げない**。セルの○×はモデルの判断であり間違い得る。位置づけは「人間が個々のセル（特に×）を安く名指しで反証できるようにする注意の誘導」であって、正しさの証明ではない。

## 3. 技法2: リンチピン分析（要の前提）— 縦の深さ

### 3-1. 仕組み

ACH が「複数の対立仮説のどれが最も反証されにくいか」（横）を問うのに対し、リンチピンは**一つの結論**（縦）に対して問う: (1) それが成り立つために欠かせない**要の前提**は何か (2) その前提を**何のデータで確認した**か (3) どの前提が崩れると結論も崩れるか＝**結論を修正すべき具体的な観測**は何か。ホイヤーの感度確認（結論が少数の材料にどれだけ依存するか）と主要前提の点検（Key Assumptions Check）に当たる。

**(3) が肝である**: 崩れる条件（`overturns_if`）に具体的なデータ・観測が挙がっていない結論は、「自分がどう崩れるかを定義していない」＝**過信の兆候**である。

### 3-2. 書き方と適用範囲

- ヘルパー: `#linchpin(conclusion: "...", pillars: ((premise: "...", verified_by: "...", overturns_if: "..."), ...))`（定義は `report_style.typ`）
- **必須**: 結論・提言章の冒頭の主要結論（1〜3個）に最低1個（Check 31。1個も無ければ不合格）。全 deep_dive には課さない＝「報告書の見出し級の判断」に限る
- 模範の型（人間のアナリストの書き方）:「B社は事業化の優先度を下げている可能性がある。**ただしこの判断は、出願の減少・主要国でのファミリーの少なさ・量産技術に関する出願の少なさに依存する**」
- 🚫 `overturns_if` は**観測できる具体的な出来事**を書く。「新しい情報が出たら」「状況が変われば」のような空文は禁止（Check 31b が出所をたどれる要素の欠落を警告）

### 3-3. 正直な限界

リンチピンをやったかは検査できるが、挙げた前提が**本当に結論の要か**（依存関係の判断の正しさ）は機械では判定できない。検査は「前提と崩れる条件を人間の前に並べる」注意の誘導にとどまる。

## 4. 技法3: ミラーイメージング点検 — 対象の合理性を自社の理屈で測らない

### 4-1. 仕組み

ミラーイメージング＝**相手も自分と同じ理屈で動くはずだ**という無意識の投影。競合・買い手・供給元の分析で「自社から見て不合理な行動」を「不合理」と断定すると、相手の置かれた文脈（補助金・サプライチェーン・既存顧客・規制・認証・地域戦略・既存事業との接点）の中では合理的な戦略を見落とす。

### 4-2. 書き方と適用範囲

- **適用条件**: `narrative_stance.code` が `competitor` / `buyer` / `supplier`（関係性立場）のとき**のみ**。`self` / `neutral` では不要
- 独立のヘルパーは使わない。対象企業を論じる章（またはミクロ分析B・提言章）に、**「対象企業から見た合理性の食い違い」を扱う一段落**を必須で置く
- 最低1点、**「自社から見ると不合理でも、対象から見ると合理的な戦略は何か」**を、上記の観点（補助金／サプライチェーン／既存顧客／規制・認証／地域戦略／既存事業との接点）から書く
- 例:「A社の低収益セグメントへの継続出願は、当社の採算基準では不合理に見える。しかしA社から見ると、同セグメントは主力製品の認証要件と共通する規格必須特許群であり、撤退はライセンス収入と交渉力の喪失を意味する——合理的な防衛である」
- `phase_d_gate.sh` Check 32 が、関係性立場なのに合理性の食い違いの記述が無い場合に警告する

### 4-3. 正直な限界

「食い違いを書いたか」は検査できるが、その食い違いの読みが**妥当か**は判定できない。

## 5. 完全な鎖の実例（マトリクス → 結論 → 提言 → リンチピン）

結論・提言章の exemplar は存在しないため、模範はここに置く。**この鎖の形**（表 → 残った仮説の明示 → その仮説を前提と名指しした提言 → 提言のリンチピン）を結論・提言章で再現すること。

```typst
// === 仮説検証サマリー章（または戦略的提言の冒頭） ===

#ach-matrix(
  question: "本母集団の出願増（2019→2024年 +34%）は、真の領域成長か、一社の急増か、収録範囲の変化か",
  hypotheses: ("真の領域成長", "一社の急増", "収録範囲の変化"),
  evidence: (
    (item: "クラスタ内出願人HHIが0.41→0.28へ低下（2019→2024年・基本統計）", cells: ("○", "×", "○")),
    (item: "2022年以降に新規出願人8社が参入（特開2024-089123 ほか）", cells: ("○", "×", "—")),
    (item: "収録年情報（2015-2024年）に変更なし（付録A）", cells: ("○", "○", "×")),
    (item: "出願総数の増加 +34%（2019→2024年）", cells: ("○", "○", "○")),
  ),
)

// 環1: 最も矛盾の少ない解釈を採用結論として明示（どの決め手がどの別解釈を退けたかまで書く）
本比較検証では、「一社の急増」という解釈はクラスタ内HHIの低下（0.41→0.28）および新規
出願人8社の参入と矛盾し、「収録範囲の変化」という解釈は収録年情報に変更が無いことと
矛盾する。最も矛盾の少ない解釈「真の領域成長」を本報告書の結論として採用する。なお
「出願総数の増加」はどの解釈とも整合するため判断の決め手にはならず、この結論の根拠には
数えていない。

// === 戦略的提言章 ===

// 環2: 提言は残った仮説を前提として名指しで置く
#recommendation-card("高", "クラスタ3（三次元積層）への出願強化",
  "本領域の出願増は一社の急増ではなく真の領域成長（仮説検証サマリーで採った結論）で
  あるため、面での技術確保が有効である。競合の新規参入8社に先行して…", timeframe: "短期(6ヶ月以内)")

// 環3: 提言のリンチピン——要の前提に「残った仮説」を据え、崩れる条件に「退けた対立仮説の復活」を書く
#linchpin(
  conclusion: "クラスタ3への出願強化（面での技術確保）を優先する",
  pillars: (
    (premise: "本領域の出願増は真の領域成長である（仮説検証サマリーで採用した結論）",
     verified_by: "クラスタ内HHI 0.41→0.28（2019→2024年）、新規出願人8社の参入（特開2024-089123 ほか）",
     overturns_if: "検討した別解釈が後から裏づけられたら——すなわち2025年公開分でHHIが再上昇し、増分の大半が特定1社に帰属すると判明した場合。その場合は面での参入でなく当該一社への個別対応（クロスライセンス・回避設計）に切り替える"),
  ),
)
```

## 6. 機械検査との対応（すべて `phase_d_gate.sh`）

| Check | 対象 | 水準 | 検査するもの／しないもの |
|---|---|---|---|
