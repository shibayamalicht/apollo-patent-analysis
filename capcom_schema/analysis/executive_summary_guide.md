## 0. 目的と位置づけ

### 本編と別冊の関係

| 項目 | 本編（`report.typ`） | 別冊（`report_executive.typ`） |
|------|-------------------|---------------------------|
| 想定読者 | 分析担当者・事業部長・技術企画 | 経営層（役員会・意思決定者） |
| 想定ページ数 | 60〜120 ページ | **8〜12 ページ（厳守）** |
| 目的 | 根拠と詳細の完全提示 | **意思決定に必要な核心のみ** |
| 読了時間 | 60〜90 分 | **15 分以内** |

要素別の凝縮量（手法詳細・ミクロ分析・クロスモジュール等）は §3-3 の表を正とする。

### 🔑 別冊の本質

**別冊は「本編の各章から段落をコピーして削った刈り取り版」ではない。**全分析から「意思決定に資する洞察」を抽出し、**Mission Objective と `query_intent` から導かれる「今回の意思決定テーマ」に即して再構成した凝縮版**である（方法は §3-2）。

## 1. 生成トリガー（Phase A STOP-GATE）

### タイミング

レポート生成依頼を受けたら、Phase A の最初（用語統一・population_meta 確認の直後、データ精読の前）に `AskUserQuestion` で確認する:

```
質問: 本編レポート（60-120ページ）に加えて、経営層向け要約版（別冊、8-12ページ）も生成しますか？

選択肢:
- ✅ 両方生成する（推奨: 経営層への提出を想定する場合）
- 📘 本編のみ
- ❓ 相談したい（位置づけ・粒度を議論してから決定）
```

**ユーザーが応答するまで次のフェーズに進まない。**AI の自己判断による省略決定は禁止。

### 選択後の扱い

- 「両方」→ 作業メモに「別冊生成フラグ = ON」と記録。Phase D で本編生成後に別冊を生成し、**両方の品質ゲート**（`phase_d_gate.sh` + §6 の別冊用チェック）を通過させる
- 「本編のみ」→ 通常通り生成。完成後「経営層向け要約版を後から追加することも可能です」と 1 行案内

## 3. 執筆ルール — エッセンス凝縮の方法

### 3-1. 「So What」原則

別冊の各段落は **「経営判断に何を意味するか（So What）」** を必ず含む。「〜が検出された」等の記述的表現は禁止。

❌ NG: 「Saturn V TELESCOPE 分析の結果、43 個のクラスタが検出された。」
✅ OK: 「技術領域は 43 個のサブドメインに分岐しており、単一戦略での全域カバーは非現実的。うち 3 つの成長リーダー・クラスタ（全体の 28%）への集中投資を推奨する。」

### 3-2. 視座の再構成（キー）

**別冊を構造化する「意思決定テーマ」は毎回 Mission Objective と `query_intent` から導く**（定型軸の機械的当てはめは不可）。

**判断の流れ**:
1. Mission Objective と `query_intent` を読み、本分析が**具体的に何の意思決定に資するか**を 1 行で書き出す
   - 例: 「CNF 構造材料領域で、自社がどの技術ポケットに注力すべきかを決める」
2. そのテーマに直結する**要点・推奨アクションのみ**を残す（本編の全項目網羅は不要）
3. 章立てもテーマに沿って再構成する（§2 テンプレートは一般形。章タイトル・順序は調整可）

**参考: よくある意思決定テーマ**: 投資領域の優先順位付け／撤退・縮小判断／提携・M&A 候補探索／競合への防衛・攻撃戦略／研究開発テーマ選定／技術ロードマップ見直し

**重要**: 上記は思考の起点にすぎず、無関係なテーマの無理な盛り込みは禁止。各要点・推奨アクションは本分析で実際に導出された結論のみに基づくこと。

### 3-3. 凝縮の具体技法

| 本編の要素 | 別冊での扱い |
|----------|------------|
| クラスタ構造の詳細（43 個全て解説） | **上位 3-5 個のみ**を意思決定テーマの視点で再構成 |
| 手法パラメータ（min_cluster_size=15 等） | **一切言及しない** |
| 個別特許ミクロ分析（15 件以上） | **意思決定テーマを象徴する代表特許 3-5 件のみ** |
| 仮説検証サマリー | **検証結果のみ**を 1 テーブルで（仮説導出過程は省略） |
| 用語解説（B 付録） | **別冊には含めない**（必要な用語は本文中で短く補足） |
| クロスモジュール分析（3 パターン × 15-20 行） | **最重要 2 パターンを各 3-5 行で要約** |

### 3-4. 数値の取捨選択

本編の数値のうち**「経営会議で即答できる数字」のみ**を残す:

- **残す**: 総件数、主要クラスタ件数、主要出願人件数、CAGR、主要シェア、市場規模
- **削る**: HHI / Entropy / Gini 等の統計指標詳細、ノイズ率、次元削減パラメータ、前処理統計

### 3-5. ビジュアルの絞り込み

本編で使った snapshot を別冊に転用する場合、**最大 3 枚まで**。選定基準:
1. クラスタ動態マップまたは MEGA PULSE 4 象限（戦略ポジション）
2. ハイプサイクル（技術ライフサイクル位置）
3. 共起ネットワークまたは俯瞰図（技術の広がり）

各ビジュアルには **キャプション + 1 行の "Takeaway"** を必ず付記する。

### 3-6. 技術→経営言語の翻訳（別冊・本編エグゼクティブサマリー共通）

経営層は技術用語ではなく **「事業インパクト（金・人・時間・リスク・意思決定）」** で読む。
APOLLO の技術的所見は、必ず次の型に翻訳してから提示する:

> 〔技術的事実〕 → だから〔競争・市場・収益・リスク上の意味〕 → ゆえに〔取るべき判断〕

#### 翻訳テーブル（技術表現 → 経営表現）

| APOLLO の技術表現（❌ そのまま出す） | 経営層向け翻訳（✅） |
|------|------|
| クラスタ0のCAGRが+254.5% | 最も急成長する技術ポケット。約3年で出願が3.5倍。先行投資の好機 |
| HHI=0.28（高集中） | 上位数社による寡占。新規参入には差別化技術か提携が必須 |
| ノイズ率18%・新興クラスタ3個 | 体系化前の萌芽領域が複数。早期に押さえれば基本特許を取りやすい |
| 媒介中心性が高い発明者X | 複数技術をつなぐキーパーソン。採用・提携・引き抜き防止の重点人物 |
| 権利化率が低い（多数出願・低登録） | 量は多いが"通っていない"出願戦略。質を伴わない出願コストが先行。模倣抑止力は限定的 |
| 少数出願だが権利化率が高い | 狙い撃ちの強い特許を持つ少数精鋭。交渉力・防衛力が高い要警戒プレイヤー |
| 学術ピークと特許ピークに3年のラグ | 研究先行で事業化はこれから。今が参入タイミングの可能性 |

#### 翻訳の必須要素（各「要点」で最低1つ）
- **金額/規模**: 市場規模・成長率・件数を投資判断に使える数字に（Web 調査と接続）
- **時間**: 「今 / 3年以内 / 5年後」のどの意思決定か
- **リスク**: 見送り時・参入時の不利益を一言
- **誰の意思決定か**: 投資・撤退・提携・採用・防衛のいずれに効くか

#### NG / OK
❌ 「権利化率分析により出願人別の登録比率を可視化した。」（記述的・技術的）
✅ 「A社は出願数首位だが権利化率は本母集団の中央値を下回る。量で先行しても"通る特許"は限定的であり、当社は出願数競争ではなく権利化率の高い重点出願で対抗するのが費用対効果に優れる。」

> **⚠️ 上記 OK 例は分析の立場 = `self`（自社視点）の書き方。**`narrative_stance.code` が `competitor` / `neutral` のときは「当社」を使わず、対象企業を企業名・「同社」の三人称・第三者の評価形で書く（正本: `terminology.md` §6-2-B）

## 4. 本編と別冊の関係 — 相互参照ルール

- 別冊の各要点・推奨アクションには可能なら **「本編 §{章名} 参照」** を付す（本編側に別冊への参照は不要）
- 両者は **同じ Mission Objective・同じ結論・同じ `population_meta`**（`voyager/context.json`）を使う。結論の食い違いや、データベース名・収録年・設計意図の再解釈は品質不合格
- **別冊も本編と同じ分析の立場（`narrative_stance`）を守る**: 呼称（`neutral` / `competitor` では「当社/弊社」禁止・三人称）だけでなく、発見・提言の中身の型まで立場に従う。本編が三人称なのに別冊だけ当事者化するのは品質不合格（型の正本: `terminology.md` §6-2-B）

## 5. 禁止事項（品質不合格）

1. **単なる刈り取り**: 本編の段落をコピーして短縮しただけのもの。必ず「経営層視点で再構成」する
2. **手法削除だけ**: 「SBERT / UMAP 等の記述を削除しただけ」の別冊は不合格。凝縮＝削除ではない
3. **ページ数超過**: 13 ページ以上は不合格。削減すること
4. **ページ数不足**: 7 ページ以下は核心が不足しているとみなし不合格
5. **結論の不整合**: 本編と食い違う結論、または別冊にしかない結論
6. **数値の不整合**: 本編と同じ数値を使う。別冊独自の再集計は不可
7. **タイトル・サブタイトルの不一致**: 別冊の `title` は本編と完全一致、`subtitle` は本編を**一字一句そのままコピー**し末尾に「 — 経営層向け要約版」を追加するだけ。**短縮・言い換え・再構成は禁止**（本冊と別冊で副題が食い違う原因）
8. **手法詳細の混入**: 「SBERT ベクトルの次元削減により…」等の記述は別冊に不要
9. **内部識別子の漏出**: `spatial_context` 等の露出禁止（正本: `terminology.md` §1）
10. **⚠️ スコープ無限化（最重要・経営判断誤導リスク）**: 外部裏付けなしの「業界では〜」「市場では〜」等で、本母集団の観察を業界全体の傾向として読ませること。経営層を誤導するため本編以上に厳格に排除し、全主張に「本母集団では〜」等の限定修飾を付す（正本: `terminology.md` §6。運用: §5-A）
11. **🚫 国籍トートロジー**: 国・地域で絞った母集団で「日本が牽引／世界をリード」と書く循環論法。限定修飾を付けても不可（正本: `terminology.md` §6-2-A）
12. **メタラベルの本文露出**: 「（事実）」「（So what）」「経営的含意:」等の層ラベルを本文に書くこと。経営層が読む完成文章では致命的（正本: `common_framework.md` §1）
13. **⚠️ スカスカ（1段落ページの量産）**: 各「要点」を 1-2 行だけ書き、空白でページ数を稼ぐこと。**別冊が"薄い"と評価される最大原因**。各ページは数値・代表特許・市場規模・ビジュアルで実質的に充填し、短ければ要点を厚くするか 2 要点を 1 ページに統合する

## 5-A. スコープ明示の徹底（経営層別冊・最優先チェック）

経営層は付録や検索式を読まず、別冊の数字をそのまま「業界の実態」として経営会議に載せる。別冊のスコープ誤読は**本編より致命的**である（規律の正本: `terminology.md` §6。以下は別冊での運用）:

### 5-A-1. エグゼクティブサマリー冒頭のスコープ注記

§2 テンプレート通り `#note-box[...]` で「本分析の対象範囲」（データベース名・対象件数・「業界全体の傾向を直接示すものではない」旨）を 3-4 行明示する。省略は品質不合格。

### 5-A-2. 各「要点」での区別

「本母集団内の観察」（限定修飾を主文に含める）と「外部裏付け付きの一般化」（#footnote で出典明示）を明確に区別し、混同しない（禁止・必須表現の正本: `terminology.md` §6-1〜§6-3）。

✅ **書き方の例（母集団限定 + 外部裏付けの分離）**:
> 要点 1: 本母集団では EV 向けパワー半導体関連クラスタが出願件数の 32% を占める。外部市場調査によれば同領域は世界全体で年 15% 成長しており#footnote[Grand View Research (URL), 取得日: 2026-04-14]、本母集団の出願集中は市場成長と整合的である。

### 5-A-3. 推奨アクションでのスコープ区別

推奨アクションにも 5-A-2 と同じ区別を適用し、根拠が「本母集団内観察」か「外部情報を加味した一般化」かを明示する。「業界トップ 3 との提携を検討」のような無限化は禁止。「本母集団の上位出願人のうち B 社は補完性が高く提携候補。ただしグローバルプレイヤーの動向は別途 Web 調査で補って最終判断」の形で書く。

### 5-A-4. 経営層別冊の追加チェック項目

別冊完成時、§6 の通常チェックに加えて以下を確認：

```bash
# スコープ注記・限定修飾の存在確認（合格: 5 件以上 = 冒頭 + 各要点 + 各推奨アクション）
grep -c "本分析の対象範囲\|本母集団\|本分析の対象\|本分析の特許群" reports/report_executive.typ

# 無限化語の過剰使用チェック（外部裏付け #footnote なしで多用していないか）
grep -cE "業界では|市場では|産業では|業界全体|市場全体|全体として|業界の主流|業界の標準" reports/report_executive.typ
```

## 6. Phase D での生成手順

### 手順

1. 本編 `reports/report.typ` を先に完成させ、`bash capcom_schema/scripts/phase_d_gate.sh` で合格を確認
2. 別冊生成フラグが ON の場合、本編の **エグゼクティブサマリー + 結論 + 推奨アクション + 主要 KPI + 最重要 snapshot** を再読し、§2 テンプレート + §3 執筆ルールに沿って `reports/report_executive.typ` を生成（単なる刈り取りは禁止）
3. 別冊の品質を以下のコマンドで確認:

   ```bash
   # 行数チェック（別冊は 250-500 行が目安。本編の 10-20%）
   wc -l reports/report_executive.typ

   # 内部識別子の混入チェック（本編と同じ用語ルール。ヒット 0 が合格）
   grep -nE "(saturnv_clusters|mega_momentum[a-z_]*|nebula_[a-z]+|atlas_statistics|explorer_[a-z]+|eagle_[a-z]+|core_classification|crew_network)\.json|\b(spatial_context|cluster_dynamics|noise_analysis|quadrant_summary|time_series|hype_cycle_phase|macro_events|npl_gap_analysis)\b|(SKILL|common_framework|data_notes|cross_module|deep_dive_guide|report_structure|quality_checklist|terminology|map_reading|patent_citation|executive_summary_guide)\.md" reports/report_executive.typ

   # サブタイトルに「経営層向け要約版」が含まれているか
   grep "経営層向け要約版" reports/report_executive.typ

   # 手法詳細の過剰混入チェック（合格: 3 件以下。多用は凝縮不足のサイン）
   grep -c "SBERT\|UMAP\|HDBSCAN\|min_cluster_size\|n_neighbors" reports/report_executive.typ
   ```

4. ユーザーに完成を報告する（本編・別冊それぞれのファイル名と行数、および `typst compile reports/report.typ reports/report.pdf` / `typst compile reports/report_executive.typ reports/report_executive.pdf` の PDF 化コマンドを提示）

### 同時生成の効率化

本編生成中（Phase C の deep_dive 執筆時から）「どの要点・推奨アクション・ビジュアルが最重要か（＝別冊にも入れるか）」をメモしておくと、別冊生成時の迷いが減る。

## 7. 執筆時の心構え

経営層向け要約版を書くときは、以下を自問すること:

- 「役員が 15 分でこの冊子を読み、翌週の経営会議で議題として出す」場面を想定できているか?
- 「So What」が各段落で明示されているか?
- 専門用語を知らない経営層が理解できるか?（用語解説なしで）
- 具体的な数値・企業名・技術名が含まれているか?（抽象論で終わっていないか）
- 本編を読まなくても「何を決めるべきか」が分かるか?

この 5 点をクリアしていれば合格品質である。
