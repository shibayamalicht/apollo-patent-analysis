# クロスモジュール分析パターン

単一モジュールの分析だけでは「片面的な結論」になりがちである。複数モジュールのデータを組み合わせることで、仮説の検証、矛盾の発見、統合的な洞察が可能になる。

> **選択的読み込み**: 本ファイルは13種のクロスモジュール分析パターン（P1-P13）を含む。**全パターンを読む必要はない。** まず「基本原則」を読み、Mission Objectiveに関連するパターンのみを選択的に読むこと。
> - 技術動態分析 → P1, P4, P11
> - キーワード・技術構造 → P2, P5, P6
> - 人的ネットワーク → P3, P9
> - ルール vs AI分類 → P7
> - 環境分析（環境分析環境コンテキスト）→ P8, P12
> - 学術-特許連携 → P13
> - 総合結論 → P10

---

## 基本原則

1. **仮説→検証のループ**: 1つのモジュールで得た結論を「仮説」とし、別のモジュールのデータで「検証」する
2. **最低5パターン**: 全ての主要な結論は最低5つのクロスモジュール分析パターンで裏付ける（P1-P13 から母集団に関連するものを優先選択。各パターン 15-20 行の仮説→検証→結論）。**各パターンは固有の問いで、参照モジュール・数値根拠・結論が他パターンと重複しないこと**。「○○論点 1, 2, 3…」と連番で同じ趣旨を言い換えて水増しするのは禁止（`phase_d_gate.sh` Check 19 で FAIL）
3. **矛盾こそ宝**: モジュール間で矛盾するデータが見つかった場合、それは重要な発見である。矛盾を隠さず、なぜ矛盾が生じるかを考察する
4. **データソース明示**: クロス分析の結果を記述する際は、どのモジュールのデータを使ったかを明示する

## P1: 技術領域 x 動態 (俯瞰図分析 + 動態分析)

### 目的
俯瞰図分析で分類された技術クラスタが、動態分析の4象限でどこに位置するかを照合し、各技術の成長段階を評価する。

### 手順
1. 俯瞰図分析の各クラスタの主要出願人リストを確認する
2. 動態分析の `entities` で同じ出願人を検索し、象限位置を確認する
3. 「クラスタXの主要出願人の大半がQIに位置する」= 成長技術、「QIIIに位置する」= 衰退技術、と評価する
4. クラスタ内で出願人の象限がバラバラな場合 → その技術領域は競争構造が分化している

### 文章化テンプレート

> 俯瞰図分析クラスタ{X}（{技術名}, {N}件）の主要出願人{A社, B社, C社}を動態分析で確認したところ、{A社}はQI（CAGR +{Y}%）、{B社}はQIV（CAGR {Z}%）に位置した。これは同クラスタ内で{解釈}を示しており、{So What}と考えられる。

---

## P2: キーワード構造 x 技術領域 (キーワード分析 + 俯瞰図分析)

### 目的
キーワード分析の共起ネットワークで検出された技術キーワードのクラスタが、俯瞰図分析の特許クラスタとどう対応するかを照合する。

### 手順
1. キーワード分析のコミュニティ上位キーワードを確認する
2. 俯瞰図分析の各クラスタのラベル・TF-IDF上位語と比較する
3. 「キーワード分析コミュニティ1のキーワード群は俯瞰図分析クラスタ3に対応」等のマッピングを作成する
4. 対応しないキーワード（キーワード分析にあるが俯瞰図分析クラスタに該当なし）= 横断的技術概念

### 文章化テンプレート

> キーワード分析の共起ネットワークで最大コミュニティを形成する「{キーワード群}」は、俯瞰図分析クラスタ{X}（{技術名}）と高い対応を示す。ただし、「{キーワードA}」はクラスタ{X}と{Y}の両方に出現し、技術横断的な概念であることが示唆される。

---

## P3: 人的ネットワーク x 技術領域 (出願人・発明者ネットワーク + 俯瞰図分析)

### 目的
出願人・発明者ネットワーク発明者/出願人ネットワークの構造が、俯瞰図分析の技術クラスタ構造とどう対応するかを照合し、「誰が」「何を」研究しているかの全体像を構築する。

### 手順
1. 出願人・発明者ネットワークのコミュニティ別メンバー（所属組織・中心人物）を確認する
2. 俯瞰図分析クラスタの主要出願人リストと照合する
3. 出願人・発明者ネットワークコミュニティ = 俯瞰図分析クラスタの場合 → 技術と組織が対応した明確な構造
4. 出願人・発明者ネットワークコミュニティが複数俯瞰図分析クラスタにまたがる場合 → 多角的な研究体制
5. ブローカー人物のクラスタ所属を確認 → 技術融合のキーパーソン

### 文章化テンプレート

> 出願人・発明者ネットワークのコミュニティ{A}（中心人物: {人物名}, {N}名）は、俯瞰図分析クラスタ{X}（{技術名}）に集中して出願している。一方、ブローカーの{人物名}（betweenness {値}）はクラスタ{X}と{Y}の両方に関与しており、{技術融合の解釈}。

## P4: 市場構造 x 競争環境 (基本統計 + 動態分析)

### 目的
基本統計の基本統計（出願人ランキング、HHI、時系列）と動態分析の動態分析を照合し、市場構造の変化を評価する。

### 手順
1. 基本統計の出願人ランキング（件数）とHHIを確認する
2. 動態分析の各象限のプレイヤー構成と比較する
3. 基本統計で上位だが動態分析でQIII/QIV → 「かつての王者」が衰退中
4. 基本統計で下位だが動態分析でQI/QII → 新興勢力の台頭
5. HHI推移と動態分析象限分布の変化を時系列で照合する

### 文章化テンプレート

> 基本統計の出願件数ランキングでは{A社}が{N}件でトップだが、動態分析ではQIV（CAGR {X}%）に位置し成長が鈍化している。一方、ランキング{M}位の{B社}（{K}件）はQI（CAGR +{Y}%）に位置し、{今後の展望}。

---

## P5: 競争比較 x 技術ポートフォリオ (キーワードドミナンス + 俯瞰図分析)

### 目的
キーワードドミナンスの出願人別キーワード優位性と俯瞰図分析の技術クラスタを照合し、各プレイヤーの技術ポートフォリオの強弱を評価する。

### 手順
1. キーワードドミナンスの出願人別優位キーワードを確認する
2. 各キーワードが俯瞰図分析のどのクラスタに該当するかをマッピングする
3. 「A社はクラスタ1・3で優位、B社はクラスタ2・5で優位」等のポートフォリオ比較を作成する
4. 複数クラスタで優位な出願人 → 広範な技術ポートフォリオ
5. 特定クラスタのみで優位 → 専門特化型の戦略

### 文章化テンプレート

> キーワードドミナンス分析によると、{A社}は「{キーワード群}」で高い優位性を持ち、これは俯瞰図分析クラスタ{X, Y}に対応する。{B社}は「{キーワード群}」で優位であり、クラスタ{Z}に特化した戦略を採っている。{両社のポートフォリオ比較からの示唆}。

---

## P6: トレンドキーワード x 動態 (キーワードトレンド + 動態分析)

### 目的
キーワードトレンドで検出された急上昇キーワードの関連出願人が動態分析の4象限のどこに位置するかを照合し、新興トレンドの担い手を特定する。

### 手順
1. キーワードトレンドの急上昇キーワードを確認する
2. 急上昇キーワードを含む出願の出願人をpatents.csvで検索する（ミクロ分析）
3. 当該出願人の動態分析象限位置を確認する
4. QI/QIIの出願人がトレンドを牽引 → 成長テーマとプレイヤーの一致
5. QIII/QIVの出願人がトレンドに乗る → 事業転換の試みの可能性

### 文章化テンプレート

> キーワード分析で急上昇キーワード「{KW}」が検出された。ミクロ分析によると、当該キーワードを含む特許{N}件のうち{A社}が{M}件を占める。動態分析で{A社}はQI（CAGR +{X}%）に位置しており、同社の成長を牽引するテーマの一つであると考えられる。

---

## P7: ルール分類 x AI分類 (ルール分類 + 俯瞰図分析)

### 目的
ルール分類のルールベース分類と俯瞰図分析のAIクラスタリングを照合し、人間の分類仮説とAIの分類結果の一致・乖離を評価する。

### 手順
1. ルール分類の分類カテゴリと俯瞰図分析のクラスタを対応づける
2. 一致 → 分類仮説がデータで裏付けられた
3. 乖離 → AIが人間の想定外のグルーピングを発見した可能性
4. ルール分類で未分類だが俯瞰図分析でクラスタ化されたもの → 新しい分類カテゴリの候補

### 文章化テンプレート

> ルール分類のルールベース分類「{カテゴリ名}」（{N}件）は、俯瞰図分析クラスタ{X}（{M}件）と{一致率}%の対応を示した。乖離分の{K}件はクラスタ{Y}に分類されており、{解釈: ルール定義の見直しが必要 / AIが新しいサブカテゴリを発見}。

---

## P8: 環境分析 x 技術動態 (環境分析 + 基本統計 + 動態分析 + 全モジュール)

### 目的
環境分析の非特許文献（論文・ニュース・政策）のトレンドと基本統計/動態分析の特許動態を照合し、外部環境と技術開発の関係を評価する。環境分析はレポートの冒頭に配置され、後続の全モジュール分析の「外部環境コンテキスト」として機能する。

### 手順
1. 環境分析のハイプサイクル分析で各技術のフェーズを確認する
2. 基本統計の出願時系列と環境分析の論文・ニュース時系列を重ねる
3. 論文ピーク → 特許ピークのタイムラグを計測する
4. 政策イベント（法改正、補助金、規制）と出願急増の対応を確認する
5. 動態分析の象限移動と環境分析イベントの因果関係を推定する
6. 環境分析 deep_diveで導出した「外部環境からの主要仮説」を一覧化する
7. **各モジュールのdeep_diveで仮説の支持/棄却を記述する**（環境コンテキスト参照）

### 環境コンテキスト参照パターン（v1.1）

環境分析 deep_diveが存在する場合、Step 1-6の各deep_diveの冒頭で以下を実施すること:
- 環境分析の主要仮説を参照し、そのモジュールの分析結果が仮説を支持/棄却するか論じる
- 例: 「環境分析で特定された{年}年の{政策/市場変化}は、本モジュールの分析結果において{クラスタ構造の変化/出願人動態}として観測された」

### 文章化テンプレート

> 環境分析のハイプサイクル分析で「{技術名}」は{フェーズ}に位置する。基本統計の時系列と照合すると、論文ピーク（{年}年）から特許ピーク（{年}年）まで約{N}年のタイムラグがある。動態分析での象限位置（{象限}）を考慮すると、{今後の見通し}。

> 環境分析で導出した仮説「{仮説}」について、俯瞰図分析クラスタ分析の結果は{支持/棄却/部分的支持}を示している。具体的には、{クラスタXの構造/出願人動態/キーワード出現パターン}が環境変化と{対応関係の詳細}。

## P9: 手動分類 x 自動分類 x 人的NW (探索的クラスタリング + 俯瞰図分析 + 出願人・発明者ネットワーク)

### 目的
探索的クラスタリングの手動クラスタリング、俯瞰図分析のAIクラスタリング、出願人・発明者ネットワークの人的ネットワークの3つを照合し、技術・人・組織の三位一体の分析を行う。

### 手順
1. 探索的クラスタリングの手動クラスタと俯瞰図分析のクラスタの対応を確認する
2. 一致する部分 → 人間の直感とAIの分析が合致
3. 探索的クラスタリングでは同一クラスタだが俯瞰図分析では分離 → 人間が見落とした技術的差異
4. 出願人・発明者ネットワークの研究者コミュニティが探索的クラスタリング/俯瞰図分析のクラスタとどう対応するかを確認する
5. 技術クラスタと人的コミュニティが一致 → 組織的な研究体制が確立している

### 文章化テンプレート

> 探索的クラスタリングの手動クラスタ「{名称}」は、俯瞰図分析クラスタ{X}と{Y}にまたがっている。俯瞰図分析が分離した理由として、ミクロ分析によると、クラスタ{X}は{技術A}、クラスタ{Y}は{技術B}に特化しており、人間の直感では1つだが技術的には2つの異なる方向性を含む。出願人・発明者ネットワークでは{人物名}がこの2クラスタのブリッジ役を担っている。

## P10: 全体統合 (全モジュール) — Mission Objectiveへの総合回答

### 目的
Mission Objectiveへの最終回答として、全モジュールのデータを統合した結論を構築する。

### 手順
1. Mission Objectiveの問い（mission.json）を再確認する
2. 各P1-P9のクロス分析で得られた洞察を一覧化する
3. Mission Objectiveへの回答に直接貢献する洞察を選別する
4. 以下の構造で最終章（Conclusion / Strategic Recommendations）を構築する:
   - 全体サマリー: 1-2段落で分析全体の結論を述べる
   - 主要な要点: 3-5項目の箇条書き（各項目に複数モジュールの根拠）
   - 戦略提言: 具体的なアクションアイテム（優先順位・時間軸付き）
   - リスク・留意点: 分析の限界・データの制約を正直に述べる

### 文章化テンプレート

> **⚠️ Mission Objective の原文を「{問い}」として転記しない。** エージェントが咀嚼し、「本分析が答えた問い」を自然な日本語で書き下すこと。
>
> 本分析では{N}モジュールのデータを横断的に分析し、{問いの咀嚼: 本分析が答えようとした内容を1行で書き下す}に対する回答を導出した。主要な要点は以下の通り:
>
> 1. **{要点1}**: {俯瞰図分析データ} と {動態分析データ} の照合から...
> 2. **{要点2}**: {キーワード分析データ} と {出願人・発明者ネットワークデータ} の照合から...
> 3. **{要点3}**: {基本統計データ} と {環境分析データ} の照合から...
>
> 以上を踏まえ、以下を戦略提言として提案する:
> - **短期（1年以内）**: {具体的アクション}
> - **中期（1-3年）**: {具体的アクション}
> - **長期（3-5年）**: {具体的アクション}

### 目的
俯瞰図分析のクラスタ動態マップ（累積件数xCAGR）と動態分析の4象限（エンティティレベル）を対比する。
クラスタレベルの成長とエンティティレベルの成長が一致するか乖離するかを分析し、

## P14: 権利化率(基本統計) x 成長率・シェア (基本統計 + 動態分析)

### 目的
「出願数 × 権利化率」の象限分析（権利化率分析）と成長率・シェア（動態分析 / 基本統計）を掛け合わせ、
「量で先行するが権利化率が低い主体」と「少数だが権利化率が高い主体」の質の差を明らかにする。
出願量だけでは見えない "通る特許" の強さで競争力を再評価する。

### 手順
1. 権利化率分析で、主要出願人/技術の出願数と権利化率を象限化（各軸の中央値で4分割）する
2. 各象限の主体を、動態分析の成長率象限・基本統計のシェアと突き合わせる
3. 「高出願・低権利化」=量産だが権利化に課題、「低出願・高権利化」=少数精鋭、を成長性と重ねて評価する
4. 権利化率は「**権利化成功＝権利継続＋失効（一度でも登録された）**」÷ 分母で算出する（失効は権利化の失敗ではなく登録後の維持判断の結果なのでマイナスにしない）。また審査係属比率が高い主体は暫定値として扱う旨を明示する

### 文章化テンプレート
> 本母集団では、権利化率分析（出願数 × 権利化率の象限）によると、{A社}は出願数最多（{N}件）だが
> 権利化率は{X}%と中央値（{M}%）を下回る一方、{B社}は出願数{n}件と少数ながら権利化率{Y}%と高い。
> 動態分析（4象限）でこれを成長率と重ねると、{B社}は{象限}に位置し、少数精鋭の重点出願が成長領域に集中している。
> 従って、本母集団においては出願量競争ではなく権利化率の高い重点出願で対抗するのが費用対効果に優れると結論づけられる。
