# KATHERINE — 対話型レポート作成モード 手順書

> **本ファイルは対話型モードの「進行様式」だけを定義する差分手順書。**
> 品質基準・成果物形式・品質ゲート・トークン効率制約はすべて自律生成モードと同一であり、
> その正本は `capcom_schema/SKILL.md`（§0 絶対遵守ゲートルール・Phase A〜D 手順・完了条件）と
> `capcom_schema/analysis/` 配下の各正本である。
> **本ファイルには数値基準（文字数・件数・行数等）を一切複製しない**（二重管理禁止。
> 基準を知りたいときは常に SKILL.md と analysis/ 正本を参照する）。
>
> 🔧 **保守注記**: SKILL.md 側でフェーズ構造・STOP-GATE 構成を変更した場合は、
> 本ファイルと `interactive/dialogue_points.md` の対応表（後述）も点検すること。

## 0-I. 対話型の絶対遵守ルール（SKILL.md §0 への追補）

**SKILL.md `## 0. 絶対遵守ゲートルール` の全項は対話型でもそのまま適用される**（項数はツール版の SKILL で異なりうるため、項番ではなく内容で参照する）。
その上で、対話型固有の違反を 3 項追加する。優先順位は §0 と同格（他の全ルールに優先）。

- **I-1. 根拠なしの提案・確定の禁止**: 分析上の判断を提示するとき（対話ポイント・STOP-GATE とも）、
  必ず「提案・根拠・別の見方・確認したいこと」の 4 部構成で提示する
  （具体形の正本: `interactive/dialogue_points.md`）。根拠を添えずに結論だけ示して確定を求めるのは違反。
  本モードの存在理由は分析過程の透明化であり、根拠開示はその中核である。

- **I-2. 対話ポイントの確定を実際のユーザー応答なしで進める行為の禁止**
  （SKILL.md §0 の「回答捏造禁止」項の拡張）: 各対話ポイント（CP-1〜CP-8）の確定は、
  `AskUserQuestion`（またはツール読替表の対応手段）を**実際に呼び、分析者が実際に選択して**
  初めて成立する。「おまかせ」も選択肢として実際に選ばれて初めて成立する。
  「分析者は同意するはず」と仮定して進むのは重大違反。

- **I-3. 迎合の禁止（指摘義務）**: 分析者の修正・異論がデータまたは analysis/ 正本の基準と
  矛盾する場合、AI は**根拠（数値・該当基準）を添えて明確に指摘する**。社交的同意による
  レビュー基準の緩和は違反。指摘してもなお分析者が確定を選ぶ場合は、判断ログに双方の根拠を
  記録した上で分析者の確定に従う。**ただし品質ゲートの機械基準（内容量・引用・用語統一等）に
  反する確定は分析者の同意があっても不可**（SKILL.md §0 第 3 項の「質的判断での上書き禁止」は、
  「分析者の同意」も上書き理由にならないと読む）。この場合は却下ではなく、基準との差分を提示して
  調整を促す。

## 1. 起動とモード判別

1. **起動条件（二重ガード）**: 次のいずれかで本モードに入る。
   - `voyager/context.json` の `report_mode` が `"interactive"`
   - ユーザーが対話型での進行を明示（例: 「対話型でレポートを作りましょう」）
2. 片方しか満たされない場合（例: `report_mode` は `"autonomous"` だが対話型の指示を受けた、
   `report_mode` は `"interactive"` だが「レポートを書いて」とだけ言われた）は、
   進行を始める前に `AskUserQuestion` で意図を 1 回確認する。**ユーザーの明示指示が
   `context.json` より優先**。確認結果は判断ログに記録する。
3. セッション途中のモード切替（対話型⇄自律型）はユーザーの明示指示で可。切替時は
   影響（以降の対話ポイントの扱い）を 1 行で説明して確認を 1 回入れ、判断ログに記録する。

## 2. 対話ツール読替表

本ファイルの `AskUserQuestion` は、使用ツールに応じて次のとおり読み替える
（STOP-GATE の読み替えと同一の対応。**読替の正本は本表**。開発リポジトリの
`capcom_schema_patches/README.md` にある実装比較表はセッションフォルダには同梱されない
開発者向け資料であり、本表を変更した場合はそちらも同期して保守する）。

| 概念 | Claude Code | Codex CLI | Antigravity IDE |
|---|---|---|---|
| 対話ポイントの確定・STOP-GATE | `AskUserQuestion` | `ask_user_question`（TUI・対話モード必須） | Artifact レビュー承認 |
| 自由記述・修正指示の受け取り | チャット | チャット | チャット / Artifact コメント |

> ⚠️ 対話型モードは **Claude Code で検証済み**。Codex CLI / Antigravity IDE では上記読替に
> よるベストエフォート対応となる（進行様式は同一、確定手段のみ読み替え）。

## 3. 進行様式 — 「提示 → 対話 → 確定」

対話型モードの基本形は次のループである。**分析者に先読みや起草を課さない**
（分析者が自発的に自分の仮説・解釈を出すのは常に歓迎し、その場合は I-3 に従い誠実にレビューする）。

1. **提示**: AI が判断案を 4 部構成（提案・根拠・別の見方・確認したいこと）で提示する
   （テンプレートと CP ごとの具体形の正本: `interactive/dialogue_points.md`）。
2. **対話**: 分析者はチャットで自由に質問・深掘り・修正指示ができる。AI は根拠を掘り下げて答える。
3. **確定**: `AskUserQuestion` で確定を取る。選択肢の基本形は
   「✅ この案で確定 / ✏️ 修正して確定 / 🔄 別案・差し替え / 🤖 おまかせ」
   （設計規則の正本: `dialogue_points.md` §共通規則）。

**運用ルール**:
- **おまかせ常設**: どの対話ポイントでも「🤖 おまかせ」を選べる。選ばれた項目は自律生成モードと
  同じ判断で進行し、判断ログに委任として記録する。確定済み判断の根拠は、後から求められれば
  いつでも開示する。**委任の既定単位は確定 1 件分**（複数章・フェーズ一括の委任は、その旨を
  明示した選択肢が選ばれた場合のみ。粒度・抱き合わせ禁止の正本: `dialogue_points.md`
  §確定の選択肢設計。Phase C 全章委任時も各章完了ごとの突合サマリ提示は省略不可）。
- **根拠は要点主義**: 根拠は「使ったデータの数値＋適用した基準＋判断手順」を簡潔に。
  長い講釈で対話とコンテキストを浪費しない。
- **用語ルールは対話にも適用**: 提示・対話の中でも内部ファイル名・内部フィールド名を出さず、
  `analysis/terminology.md` の読者向け呼称を使う（例: 「母集団タイプの判定基準では〜」と言い、
  内部ファイル名を口にしない）。レポート本文の用語ルールと同一。
- **自由記述はチャット・確定はツール**: 長文のドラフトや詳細な修正指示が必要な場合は、
  分析者に `reports/_analyst_notes.md` へ書いてもらい AI が読む方式でもよい
  （内部作業メモ扱い・レポート本文への転載厳禁。`_carryover.md` と同じ規律）。

## 4. Phase 0 — セッション開始（対話型のみの追加ステップ）

1. 環境準備（依存確認）: SKILL.md「環境準備」と同一。
2. `analysis/terminology.md` を読了する（SKILL.md Phase A STEP 0 と同じ最優先ルール。
   対話の用語にも適用するため、対話型ではセッション冒頭に読む）。
3. `AskUserQuestion` で**対話の深さ**と時間配分を確認する:
   - **標準（推奨）**: 全 8 対話ポイント（CP-1〜CP-8）で提示→確定を行う
   - **ライト**: CP-2（母集団タイプ）・CP-6（仮説と検証）・CP-8（結論の確定）の 3 箇所のみ
     対話し、他は自律生成モードと同じ進行とする（確定済み判断の根拠は求めに応じて開示）
   - 時間配分: 1 セッションで通すか、複数セッション（推奨）に分けるか
   - 深さはセッション途中でも変更可能（変更は判断ログに記録）
4. 進め方を一言で説明する:
   「各判断ポイントで、私の案と根拠をお見せします。選ぶ・直す・おまかせ、どれでも構いません。
   疑問点はいつでも聞いてください。」
5. `reports/_carryover.md` を作成し（SKILL.md の手順と同一。テンプレート:
   `templates/carryover_template.md`）、判断ログに `[対話]` タグでセッション開始
   （深さ・時間配分の確定値）を記録する。

## 5. Phase A〜D — SKILL.md の手順に対話ポイントを重ねる

**進行の正本は SKILL.md の「レポート生成 4 フェーズ手順」**。全 STOP-GATE・ワンショット統計
スクリプト・`_phase_a_decisions.json` 保存・`select_representatives.py`・`phase_c_gate.sh` /
`phase_d_gate.sh`・成果物・完了条件は一切変えずそのまま実施する。

本モードで変わるのは次の 2 点のみ:

**(a) 8 つの対話ポイント（CP）を該当ステップに重ねる**（定義の正本: `interactive/dialogue_points.md`）

| CP | 内容 | 重ねる先（SKILL.md 内の位置） | ライト時 |
|---|---|---|---|
| CP-1 | 検索式の読解 | Phase A STOP-GATE A（query_logic 指定時のみ） | 自律進行 |
| CP-2 | 母集団タイプの判定 | Phase A STOP-GATE C | **対話** |
| CP-3 | サブクエスチョン | Phase A サブクエスチョン化 STOP-GATE（query_intent 指定時のみ） | 自律進行 |
| CP-4 | マップ読解 | Phase B Evidence 精読（ステップ 2-3） | 自律進行 |
| CP-5 | クロスパターン選択 | Phase B STOP-GATE 1 | 自律進行 |
| CP-6 | 仮説と検証 | Phase B クロス分析実行（ステップ 5-6） | **対話** |
| CP-7 | 統合インサイト | Phase C 各モジュール deep_dive の統合インサイト節 | 自律進行※ |
| CP-8 | 結論の確定 + WARN トリアージ | Phase D 結論章執筆・gate 実行後 | **対話** |

※ ライトでも分析者が希望すれば 2〜3 モジュールに限定して CP-7 を実施してよい。

**(b) 既存 STOP-GATE の提示に根拠説明を添える**（I-1 の適用）:
CP が重ならない既存 STOP-GATE（別冊確認・NEBULA 戦略・タイトル 3 案・Web 調査テーマ・
Phase C/D 計画確認等）も、提示時に「なぜこの案か」の根拠を 1〜3 行添える。
選択肢・確定手順は SKILL.md の定義のまま変えない。

## 6. 記録（判断ログ）

- 各 CP の確定ごとに `reports/_carryover.md` の判断ログへ `[対話]` タグ付きで 1 行記録する:
  `[YYYY-MM-DD / Phase X / thread N] [対話] CP-n: AI提案「要旨」→ 分析者: 承認/修正「要旨」/委任 → 確定「値」（理由: 1行）`
- おまかせ（委任）は `[対話→委任]` と明記する。深さ変更・モード切替も判断ログに記録する。
- セッション完了時、`_carryover.md` の申し送り節に**対話サマリ**（分析者判断で確定・修正された
  主要ポイント）を数行で追記する。
- 判断ログ・対話サマリ・`_analyst_notes.md` は内部作業メモであり、`report.typ` /
  `report_executive.typ` への転載は厳禁（`_carryover.md` と同一規律）。

## 7. コンテキスト運用

- 対話型は往復が増えるため、**「1 スレッド = 1 フェーズ」分割を標準とする**
  （自律生成モードでは推奨、対話型では標準）。
- 中断・再開は SKILL.md のフェーズ間引き継ぎ日誌の固定手順をそのまま使う
  （`ls reports/` → `_carryover.md` → `_phase_a_decisions.json` → 着手フェーズのガイド）。
  判断ログの `[対話]` エントリが対話の記憶を引き継ぐ。再開時は対話の深さの確定値も
  判断ログから復元する。
- コンテキストが限界に近づいたときの「先に日誌へ保存 → `/compact` → 再開後に必ず質問」
  プロトコル（SKILL.md §0 のコンテキスト限界時 STOP-GATE 死守項）は対話ポイントにもそのまま適用する。
- トークン効率制約（サブエージェント禁止・ワンショット統計・再読み込み禁止・段階的読み込み）は
  自律生成モードと同一に適用する。

## 8. 完了条件

SKILL.md の各 Phase 完了条件・`phase_c_gate.sh` / `phase_d_gate.sh` 合格（同一基準・無改修）に
加えて、次を満たすこと:

- [ ] **発動した**全対話ポイント（CP-1 / CP-3 はそれぞれ発動条件〈query_logic / query_intent
      指定時〉を満たした場合のみ対象。深さがライトの場合は CP-2 / CP-6 / CP-8）について、
      確定または委任が判断ログに記録されている。発動しなかった CP-1 / CP-3 は
      「未指定のためスキップ」の旨を判断ログに 1 行記録する
- [ ] Phase D gate の WARN について、分析者による直す/残すの判断と理由、または委任の記録
      （`[対話→委任]`。この場合「WARN を AI 判断で処理した」旨を最終報告に明記）が
      判断ログに記録されている（CP-8 の一部）
- [ ] `reports/report.typ`・`reports/report_executive.typ`（生成した場合は PPTX も）に
      `SKILL_INTERACTIVE` / `dialogue_points` / `_analyst_notes` の文字列が **0 件**であることを
      grep で確認した（内部ガイドファイル名の露出は用語統一ルール違反として修正する）
- [ ] 対話サマリが `_carryover.md` の申し送り節に追記されている
