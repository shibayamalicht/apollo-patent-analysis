# APOLLO v10.0.0

**A**dvanced **P**atent & **O**verall **L**andscape-analytics **L**ogic **O**rbiter

**特許情報分析の操縦席 — 母集団の設計から戦略レポートまで、判断とその根拠を残しながら。**

> "Houston, we have ~~a problem~~ a report — and this time, the flight recorder was running."

特許リスト（CSV / Excel）を取り込むと、技術俯瞰図・動態分析・キーワード分析・ネットワーク分析・環境分析までを
生成し、AIエージェント（Claude Code 等）と連携して数十ページ級の分析レポートに仕上げる、
Streamlit 製の特許情報分析プラットフォームです。**LLM の APIキーは不要です。**

---

## 🛰️ これは何？

APOLLO は「分析 → 図の収集 → レポート化」を1本の流れにした分析プラットフォームです。
想定しているのは**本格的な分析者** — 分析結果を上司や顧客に説明する責任を負い、
「なぜこの粒度なのか」「何を除外したのか」に答える必要がある人です。

そのため APOLLO は、答えを見せて終わりにせず、**分析者が答えを出すのを助ける**方に振っています。
粒度を決めるパラメータは実行ボタンの隣にあり、地図の品質指標は常に見えていて、
下した判断は**フライトレコーダー**にすべて記録されてレポートの付録になります。

```
特許リスト（CSV / Excel）
   │
   ▼
Mission Control で母集団を設計・取込・前処理
   │
   ▼
APOLLO で分析・可視化 — 俯瞰図・動態・キーワード・ネットワーク・探索的クラスタリング・環境分析
   │
   │  気に入った図を「📸 レポート用に保存」で収集（分析条件は自動で記録）
   ▼
CAPCOM でパッケージ
   │
   ├─ ⚡ チャットキット   → ChatGPT / Claude / Gemini 等に貼る → レポートの骨格（5分）
   └─ 📦 レポート用ZIP    → Claude Code / Codex CLI / Antigravity → Typst / PDF / PPTX（本格）
```

## ✨ 5つの特徴

### 1. 操縦桿は分析者の手元にある

クラスタの粒度・近傍数・乱数シードは**実行ボタンの隣**にあり、詳細設定は既定で開いています。
地図の品質（DBCV・クラスタ数・未分類率・採用した粒度）は結果の隣に常時表示され、
「この地図をどこまで信じてよいか」がその場で分かります。
粒度は自動掃引に任せることも、自分で決めることもできます。

### 2. 自動クラスタリングに納得できなければ、自分で囲める

**EAGLE（探索的クラスタリング）** は、俯瞰図の上を投げ縄で囲んで独自のクラスタを定義するモジュールです。
アルゴリズムが引いた境界に違和感があるとき、分析者の目と知識で引き直せます。

### 3. フライトレコーダー — 分析条件が丸ごと残る

母集団の来歴（読み込んだファイル・件数・結合と重複除去・除外語・要約の有無・分類コードが IPC か FI か）と、
各モジュールの実行条件（粒度・クラスタ数・未分類率・品質指標・乱数シード・所要時間）を**自動で記録**します。
記録は画面のカード・ZIP 内の `flight_recorder.json`・**レポート付録の「分析条件」表**の3か所に出ます。

記録は全パラメータを対象にしますが、**レポートへの出し方は3層に分かれています**。

| 層 | 記録する内容 | レポートでの扱い |
|---|---|---|
| 1 | 母集団の来歴 | **本文で使える**（母集団の定義章・信頼性注記） |
| 2 | 粒度・クラスタ数・未分類率・品質指標 | **「結論の前提と見直しのサイン」の材料**。数値ではなく「粒度を上げれば分割されうる」等の条件文に変換して書く |
| 3 | 近傍数・最小距離・乱数シード・モデル名 | **付録の表にだけ**。本文への数値記載は禁止 |

層を分けずに丸ごと AI へ渡すと本文に内部パラメータが漏れるため、層は JSON 内に明示して運び、
品質ゲートでも露出を検査します。

### 4. 母集団の設計から始まる

分析の質は母集団で決まります。APOLLO の入口 **Mission Control** の先頭タブは「0. 母集団設計」で、
検索式・その設計意図・収録年・使用したデータベース名を記録します（すべて任意入力です）。

| 項目 | レポートでの扱い |
|---|---|
| 母集団論理式の設計意図 | AI が理解を対話で確認したうえで「分析の視座」として全編に反映 |
| 母集団論理式（検索式） | 付録に全文掲載 + 分析で考慮 |
| 収録年情報（**検索日を推奨**） | 対象期間の明記 + 時系列分析の解釈に反映（下記） |
| 使用した特許データベース名 | 付録とカバレッジ注記に反映。**未入力なら「提供された特許データセット」と汎用表記され、AI が具体名を勝手に補うことはありません** |

**収録年には検索日（データを取得した日）を入れてください。** 直近の出願は公開まで最大18ヶ月かかるため、
データ末尾の件数減少が公開遅延による見かけのものか実質的な減少なのかは、検索日が分からないと判別できません。
検索日を書くとレポートが「{検索年−1}年以降は公開遅延によりほぼ含まれない」と具体年で注記します。
無い場合はデータに含まれる出願年の範囲で代替されますが、それは収録範囲そのものではないため、
注記は具体年にならず、直近の増減についても断定を避けます。

### 5. 保守フリー設計

LLM API 依存がないため、特定モデルの提供終了や世代交代に影響されず動き続けます。
分析エンジンはコアライブラリ [patiroha](https://github.com/shibayamalicht/patiroha) に集約されています。

## 🗺️ 使い方の流れ

1. **Mission Control（母集団設計・データ準備）** — 「0. 母集団設計」で検索式や収録年を記録し、
   「1. データ取込」で特許リスト（CSV / Excel）を取り込みます。
   **J-PlatPat の検索結果CSVは自動認識**され、カラム紐付け・区切り文字まで自動設定されます
   （分割ダウンロードした複数ファイルは、まとめて選ぶと自動で結合・重複除去）。
   その他のデータもカラムの割り当てが列名から自動推定され、「2. カラム紐付け」で確認・修正できます。
   ノイズになる定型語は「3. 除外ワード」で整理。必要なら「4. 外部データ取込（任意）」で
   論文・ニュース・政策・市場データを追加。最後に「5. 前処理」を実行すると全モジュールが解放されます
2. **分析** — 各モジュールで条件を決めて実行 → 気に入った図を「📸 レポート用に保存」で収集。
   保存した図・分析データ・**実行条件**は記録セッションに自動で蓄積されます
   （前処理完了時に自動開始されるので、開始し忘れの心配はありません）
3. **CAPCOM（レポート生成）** — ミッション目的（何を明らかにしたいか）を書いて、
   ⚡ チャットキット（かんたん・5分）か 📦 レポート用ZIP（本格）を出力

## 📦 モジュール構成

サイドバーは **① 母集団 → ② 分析 → ③ レポート** の3グループ。ナビに出るのは機能名だけで、
コードネーム（Saturn V・EAGLE 等）は各ページの見出しに小さく副えています。

| グループ | 機能名 | コードネーム | 内容 |
|---|---|---|---|
| ① 母集団 | 母集団設計・データ準備 | **Mission Control** | 母集団設計の記録・取込・カラム紐付け・除外ワード・外部データ(NPL)取込・前処理 |
| ② 分析 | 基本統計 | **ATLAS** | 出願推移・出願人ランキング・分類コード（IPC/FI）分布・市場集中度（HHI/Entropy/Gini）・権利化率マップ（出願数×権利化率） |
| | ルール分類 | **CORE** | 論理式（AND/OR/NEAR/ADJ・分類コードも指定可）による技術×課題×解決手段の分類。分類コードは `H02J3/00` でも `H02J 3/00` でも書け、データ側がどちらの表記でも一致します。ルール設計はチャットAI用キットで支援 |
| | 俯瞰図分析 | **Saturn V** | SBERT×UMAP×HDBSCAN の技術地図・ノイズ（萌芽候補）分析・クラスタ動態マップ・ドリルダウン |
| | 探索的クラスタリング | **EAGLE** | 投げ縄による手動クラスタリング・クラスタ動態マップ |
| | 動態分析 | **MEGA** | 成長率(CAGR)×活動量の4象限で技術テーマの勢いを判定。分析軸は出願人/分類コード(IPC/FI)/Fタームの3軸 |
| | キーワード分析 | **Explorer** | 共起ネットワーク・トレンド分析・文脈検索(KWIC) |
| | 出願人・発明者ネットワーク | **CREW** | 共同出願・発明者の協業構造（媒介中心性・コミュニティ検出） |
| | 環境分析 | **NEBULA** | 論文・ニュース・政策・市場と特許のギャップ分析、学術クラスタ分析、Hype Cycle |
| ③ レポート | レポート生成 | **CAPCOM** | チャットキット（経路A）+ AIエージェント連携ZIP（経路B） |

### ルール分類で分類コード（IPC / FI）を条件に使う

論理式にコードをそのまま書けます（例: `H02J3/00 + (需給 * 調整)`）。

- メイングループだけを書けば配下のサブグループにも当たります（`H02J13/00` は `H02J13/00,301@A` にも一致。
  別グループの `H02J13/12` は拾いません）
- コードを照合対象に含めるには「分類コード（IPC/FI）も検索対象に含める」を ON にしてください
  （分類コードの列があり要約が無いデータでは、前処理の完了時に既定で ON になります）

## 🧭 v9.1.0 からの進化

詳細は [RELEASE_NOTES.md](RELEASE_NOTES.md) を参照してください。

**新機能**

- 🎙️ **フライトレコーダー** — 母集団の来歴と各モジュールの実行条件を自動記録。画面カード・`flight_recorder.json`・レポート付録の3か所へ出す。層1/2/3 で本文・見直しのサイン・付録に振り分ける
- 🎯 **母集団設計を入口に** — 検索式・設計意図・収録年・データベース名の記録を Mission Control の先頭タブへ（従来は CAPCOM ページの奥）
- 🎛️ **パラメータの前面化** — 粒度・近傍数・乱数シードを実行バーへ昇格。詳細設定は既定で開き、品質指標（DBCV・クラスタ数・未分類率・採用した粒度）を結果の隣に常時表示。乱数シードを変えて再描画すれば、結論が配置に依存していないかを確かめられます

**UI 刷新**

- 🛰️ **グラファイトの計器盤** — サイドバーを暗い計器盤に、操作するコンテンツ領域は白基調のまま。図の描画領域を白に保つのは、俯瞰図の12色パレットが白地で色覚検証されているため
- 🪐 **軌道ロゴマークと線アイコン** — サイドバーとページ見出しにロゴマークを配置。ナビの絵文字を全廃し線アイコンに統一
- 🗂️ **3グループナビ** — 「① 母集団 → ② 分析 → ③ レポート」に再編（`st.navigation`）。データ状態カード（ファイル名・件数・前処理状態・📸枚数・飛行記録件数）を常駐表示
- 🖼️ **「この図の見方」カード** — 主要な図の直下に読み方ガイドを設置（既定は折りたたみ。熟練者の視界を塞ぎません）
- 🛟 **統一データガード** — データ未準備のままどのページを開いても、同じ案内と「Mission Control を開く」ボタンを表示

**取込・分析**

- 🗾 **J-PlatPat CSV 対応** — 検索結果CSVを自動認識（要約なし形式にも対応）。分割ダウンロードした複数ファイルのまとめて読込（自動結合・重複除去）、必須カラムの緩和（発明の名称・出願番号・出願日・出願人の4つで分析可）、分類コードは IPC / FI の両対応、文献URL列があれば図の点クリック詳細から原文を開けます
- 🗺️ **俯瞰図の統一デザイン** — 俯瞰図ファミリー6箇所（Saturn V メイン／ドリルダウン・EAGLE メイン／ドリルダウン・NEBULA 学術・MEGA ドリル）を同一デザインに刷新。離散固定色（色覚検証済み12色）・点と勢力圏とラベルの色一致・平滑な勢力圏・クラスタ別の地形図風密度。EAGLE だけは未割り当ての点を沈めません（自動分類の外れ値と違い、これから投げ縄で掴む作業対象だからです）
- ⚖️ **権利化率に審判系を算入** — 登録後の争い（異議申立・無効審判）は権利化成功に算入、登録前（拒絶査定不服）は未確定として区別

**レポート生成**

- 🧾 **レポート本文の呼称を機能名に統一** — 本文・別冊・スライドの分析名を機能名（俯瞰図分析・動態分析 等）で出力。読者はモジュールのコードネームを知らないためです。品質ゲートにコードネーム露出の警告チェック（Check 8g）を追加
- ⚡ **チャットキット** — プロンプト＋証拠画像を1クリックでパッケージし、任意のチャットAIに貼るだけでレポート骨格を生成（APIキー不要）。AIの応答を貼り戻して読む専用ビューア付き
- 📔 **CAPCOM 1ページに統合** — 旧 VOYAGER + CAPCOM を統合。Export→ZIP の2段操作を1ボタン化
- 🎬 **記録セッションの自動開始** — 前処理完了時に自動で始まり、「開始し忘れてデータが溜まっていなかった」を根絶

**廃止したもの**

- ❌ **Gemini API による自動レポート（旧 VOYAGER）** — LLM API 依存を持たない保守フリー原則により削除。同じ役割はチャットキットが引き継ぎました。ZIP 内部の `voyager/` パス名・キー名は互換のため不変です

**修正した不具合**

- **レポートの代表特許にネットワークのハブ企業が1社も選ばれない** — 参照するデータのキー名が実際の出力と食い違っており、該当枠が常に空でした。エラーも警告も出ないため、レポートを見ても欠落に気づけない種類の不具合です
- 基本統計のバークリックで別タブの図に化ける（`@st.fragment` のクロージャ）／勢力圏と点の座標ズレ（`Scattergl` と SVG の混在）／ステータス空欄の特許が内訳グラフから消える（NaN 落ち）／密度マップの端が四角く切れる／出願人を発明者用の区切り文字で分割してしまい共同出願が0件になる — ほか

**互換性**

- ✅ 分析エンジン（patiroha）・レポート品質ゲート（Check 1〜37）・対話型モード（KATHERINE）・ZIP セッション構造: **v9.1.0 と互換**。ZIP 内部のファイル名・データ構造は不変で、v9 で確立したレポート生成ワークフローがそのまま動きます（`flight_recorder.json` は後方互換な追加です）

## 🖥️ ローカル実行

```bash
python3.12 -m venv .venv && source .venv/bin/activate   # Windows: py -3.12 -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
# → http://localhost:8501
```

⚠️ **Python は 3.10 〜 3.12 を使ってください。3.13 以降では動きません。** 数値計算の土台に
`numpy` 1.x 系を使っており、その最終版（1.26.4）のビルド済みパッケージが Python 3.12 までしか
提供されていないためです。**最新版の Python を入れると失敗します**（https://www.python.org/downloads/
の一覧から `3.12.x` を選んでください。既存の版と共存できます）。

Linux では CPU 専用の PyTorch を自動で選びます。通常の PyTorch は GPU 向けの CUDA 一式（数GB）を
連れてくるため、GPU の無いサーバーやホスティングではインストールが失敗するためです。
Mac / Windows は影響を受けません。

初回起動時に文埋め込みモデル（SBERT）のダウンロードが走ります。

## 📋 データ形式

CSV または Excel。**必須は4カラム**です。

| 区分 | カラム | 備考 |
|---|---|---|
| 必須 | 発明の名称 / 出願番号（または文献番号）/ 出願日 / 出願人 | |
| 推奨 | 要約 | あると俯瞰図の精度が大きく上がります。無い場合は名称だけで分析し、警告を表示します |
| 任意 | 請求項 / 分類コード（IPC または FI）/ Fターム / ステータス（法的状態）/ 発明者 / 文献URL | |

カラム名は自動推定され、「2. カラム紐付け」で確認・修正できます。
J-PlatPat の検索結果CSVはヘッダから自動認識され、紐付けと区切り文字がプリセットされます。

## ⚠️ 注意事項・既知の仕様

- **ブラウザを閉じる／再読み込みするとデータ・分析結果・保存した図はすべて消えます**（Web対応のインメモリ設計）。分析を終えたら CAPCOM でチャットキットや ZIP を必ず手元に保存してください
- サイドバーの状態カードは操作1回分遅れて更新されることがあります（描画順の性質）
- 📸 保存時にまれに「Bad message format」が出ることがありますが、自動回復します
- 俯瞰図のラベルはドラッグで移動できます。ラベル同士が重なった場合はドラッグで回避してください
